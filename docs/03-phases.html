The time contract

Day1 = 10 October. Day40 = 18 November 2026. Plan on six focused development hours/day, roughly240 hours total, with most final days reserved for failures and submission. This is an estimate, not a guarantee of completion by a solo developer.

The competition deadline is 18 Nov,12:00 PST =20:00 UTC =19 Nov,01:00 Pakistan time. Our submission target is 17 Nov,20:00 UTC, giving a full day for a real submission problem. Official deadline and rules ↗

The scope is frozen; fixes, security patches and changes required to make an included feature work are allowed. Extra features are not. A phase is complete only when its observable gate passes. Calendar progress alone does not pass a gate.

A

Phase A · Foundations and a real data round trip

Days 1–6 • 10 Oct–15 Oct • F01

Build only this

Data rights/acquisition and Quest tester confirmed by Day2. Remove starter content; implement schemas, capped ZIP/PCD/OpenLABEL parsing, converter and independent validator. First real clip displayed and exported unchanged. CI and source repo working. First seated hand ray test on Day4.

Required exit proof

A passing real-input → untouched export → independent reimport; valid source coordinates; live provider capability probe; named hardware and reviewers.

If the gate fails

If rights/device/model unavailable by Day2, stop scope execution and resolve that blocker. If data still cannot round-trip by Day6, fix it before UI polish.

Tests: DATA-01, DATA-02, GEO-01. Use Guide04 file entries for this phase and Guide05 test procedures.

Phase C · Hands-first review and precision editing

Days 13–20 • 22 Oct–29 Oct • F03, F06

Build only this

Point scene, box selection, isolate, frame step, view reset and tabletop rotation/scale. Spatial panel, manual moves/sizes/yaw, preview/approve/reject/keep/duplicate confirmation, undo and exit. Comfortable text and tracking-loss cancellation.

Required exit proof

If hands precision or performance fails, simplify scene and fix controls. Do not add voice, controllers-required fallback or unrelated features.

Dependency order and daily routine

Never reverse this order

  1. Rights, real data, hardware and provider access.
  2. Canonical input/output and source-coordinate proof.
  3. Private persistence and safe edit transaction.
  4. Hands inspection and precision controls.
  5. Measured checks, agent and complete export.
  6. Real people, production and submission.

Every day

  1. Choose the phase’s smallest unfinished acceptance task.
  2. Read its file card and tests first.
  3. Write a coherent slice; run its meaningful checks.
  4. Save the evidence with date and commit.
  5. Commit and push working code.
  6. Update the gate honestly; record one remaining blocker.

Non-negotiable freeze

No new input formats, model training, live scanning, multiplayer, voices, accounts for teams, billing, social features, game mechanics, landing-page marketing systems or unexplained “future” AI abilities. Do not consume the final week with a redesign.

Any necessary change has a small record: what failed, affected files/tests, compatibility decision and new evidence. The application acceptance contract does not silently grow. If a requirement becomes impossible, mark the product blocked instead of redefining success after the fact.
