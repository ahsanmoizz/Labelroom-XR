Step 1 — acquire the requirements before feature coding

Real blockers are handled now. If a real licensed clip, Quest tester or usable model endpoint is still missing after Day 2, do not proceed into a 38-day build pretending that the missing requirement will fix itself.

Step 2 — install tools on Windows

Download the official Node 24.19.0 x64 MSI from the pinned Node release ↗. Install Git for Windows from git-scm.com, GitHub CLI from cli.github.com, and VS Code from code.visualstudio.com. Reopen PowerShell after installation. Installer-created PATH changes only reach a new terminal.

node --version
npm --version
git --version
gh --version
# Expected Node: v24.19.0. Do not replace HOME or other system variables.
# Install uv using its official Windows installer:
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
# Close and reopen PowerShell, then:
uv --version
uv python install 3.12.14

Official uv installation instructions ↗. Python is managed by uv; do not search for a nonexistent Windows installer for a security-only Python release. Full browser test automation needs a Playwright Chromium download later.

Step 3 — extract and start the supplied project

Download the project ZIP, extract it to C:\dev\labelroom-xr, and open that folder in VS Code. Do not run the generator again over this pack. The commands below assume this exact directory.

Set-Location C:\dev\labelroom-xr
powershell -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
# Bootstrap runs npm ci, copies .env.example only if .env.local is missing,
# then checks types, starter geometry tests, build and pack prerequisites.
Set-Location tools\converter
uv sync --frozen
Set-Location ..\..
npx playwright install chromium
npm run dev
# IWSDK launches its managed local browser / XR emulator.
# Stop it when finished:
npm run dev:down

Expected result: a clear build-scaffold status and IWSDK initialization. There is no review UI yet. A green npm run verify at this stage is a scaffold result, not a product-release result.

Linux/macOS equivalent after installing Node 24.19.0 and uv:

cd labelroom-xr
bash scripts/bootstrap.sh
uv sync --project tools/converter --frozen
npx playwright install chromium
npm run dev

Do not install the large optional IWSDK reference-model corpus or Meta headset CLI unless you choose to use those developer tools. They are not required to run our app. Use the official HTTPS staging URL for remote headset testing; this avoids local certificate/network surprises.

Step 4 — link GitHub to ahsanmoizz

The project uses https://github.com/ahsanmoizz/labelroom-xr.git. A new private repository is the starting choice. The script refuses to replace an unrelated remote, push over existing remote commits, or use another GitHub account.

Set-Location C:\dev\labelroom-xr
gh auth login
# Select GitHub.com, HTTPS, and authenticate as ahsanmoizz.
gh api user --jq .login
# Must print ahsanmoizz.
powershell -ExecutionPolicy Bypass -File scripts/github-link.ps1
git remote -v
git status
# Confirm repository and pushed commit:
gh repo view ahsanmoizz/labelroom-xr --web

If the repository already has commits, the script stops intentionally. Run git fetch origin, inspect the branch history, and reconcile it without force-pushing. This is a safety stop for an actual conflict, not an expansion of scope. Configure Git author identity on your own machine if Git asks for it.

No GitHub remote was created or pushed by this session. The available connector can read your account, but cannot create a repository. The local repository and this script make that remaining step concrete.

Day2 — verify real model access before building the agent

Create .env.probe.local privately containing GROQ_API_KEY=your_key. This ignored local file is only for the account capability probe, which may incur a small provider charge. Never put the key in a screenshot, chat message or commit. The probe requests a function call; it does not run geometry or prove the product agent works.

node --env-file=.env.probe.local scripts/probe-model.mjs

A successful result records model access only. Full live agent tests remain AI-01 in PhaseD. Delete the local probe key file after the test; production uses Supabase Edge secrets.

Step 6 — fill environment and apply backend only when written

In .env.local, fill the four public values from .env.example. The publishable key is allowed in the browser. The service-role/secret key, Groq key, SMTP key and Turnstile secret are private.

VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_PUBLISHABLE_KEY
VITE_TURNSTILE_SITE_KEY=YOUR_PUBLIC_SITE_KEY
VITE_APP_ORIGIN=https://YOUR_STAGING_PROJECT.pages.dev

After Phase B migrations/functions are implemented and tested:

npx supabase login
npx supabase init
# init is only needed once because config.toml is a Phase B file.
npx supabase link --project-ref YOUR_STAGING_PROJECT_REF
npx supabase db push --dry-run
npx supabase db push
# Fill supabase/.env privately from supabase/.env.example.
npx supabase secrets set --env-file supabase/.env
npx supabase functions deploy project-admin
npx supabase functions deploy agent
# Later PhaseE server-only cleanup, with secret verification implemented:
npx supabase functions deploy cleanup --no-verify-jwt
Do not deploy these functions as empty placeholders. Keep gateway JWT verification enabled for user-facing functions. Our shared auth module must also call auth.getUser on the user JWT before any privileged work. Guide 05 requires forged/expired/missing-token tests. Until that code passes, deploy nothing.

Use cloud staging for development. Docker/local Supabase is excluded from the required setup, saving memory. Production will be a separate project, not a rename of the test database.

Step 7 — real data acquisition and conversion

Preferred demo source: a short PandaSet sequence. Its devkit describes world-coordinate XYZ, timestamps and cuboid annotations. The devkit code licence is Apache2; that is not automatically the data licence. The actual sequence archive includes LICENSE.txt. Record that licence, source, attribution and SHA256 before redistribution. Official devkit ↗ · Dataset paper ↗

Research found the old official download routes unavailable. MathWorks provides a documented PandaSet subset download ↗ with PCD and ground truth, but it is large and has different packaging. We are not treating it as a drop-in, already verified demo bundle. By Day2 obtain an original licensed copy, ask the publisher for working access, or use a directly supplied real PCD/OpenLABEL clip with documented rights. No new format adapter is silently added.

# After convert.py is implemented in Phase A, from repository root:
uv run --project tools/converter python tools/converter/convert.py --input data/private/001 --start 0 --frames 10 --out data/private/clip.lrx.zip --trusted-pickle --license data/private/001/LICENSE.txt
# Or the supported generic input path:
uv run --project tools/converter python tools/converter/convert.py --pcd-dir data/private/pcd --labels data/private/labels.openlabel.json --license data/private/LICENSE.txt --out data/private/clip.lrx.zip
uv run --project tools/converter python tools/converter/validate.py data/private/clip.lrx.zip

The browser never accepts pickle. Python pickle can execute code; --trusted-pickle acknowledges local use of known-trusted original files only. Do not upload pickle, whole camera archives or customer secrets. Never silently downsample to meet limits; reject oversized input and ask for an explicit smaller clip.
