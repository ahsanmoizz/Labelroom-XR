What a passing test means

A feature passes only when the stated outcome is observed. Unit tests prove numerical/state rules. Staging tests prove actual auth/database/storage behavior. A real Quest proves hands and performance. Real reviewer sessions provide limited value evidence. None of these replaces the others.

All product test groups below start unpassed. The supplied small geometry suite is the only implemented product-logic suite today. Do not run empty suites and describe the whole product as tested.

After Edge files exist, run npx deno check on each function entry before deployment. Run tests relevant to the change; rerun full critical suites before release. Do not silently skip a failing test or reduce a threshold after measuring poor results. Provider mocks only test boundary behavior; live model evidence is separately required.

Standard test cards

DATA-01 · Real input integrity A

Procedure: Use a known licensed clip and small independent fixtures. Test valid binary/ASCII conversion, sourceOrigin, source-world yaw mapping, IDs, units/timestamps, missing hashes, malformed JSON and preservation of unknown metadata.

Pass / fail: Valid input parses; mismatched hash/NaN/unsupported quaternion/missing licence fails with location; independent validator reconstructs source coordinates within1e-5m for labels. Float32 points tolerance ≤1e-3m within250m.

Write/run here: tests/unit/data.test.ts; tools/converter/test_converter.py

DATA-02 · Hostile input and ceilings A

Procedure: Use tiny controlled entries declaring excessive sizes; traversal ../, absolute/drive paths, duplicate names, nested archives, truncated payloads,11frames,200001points,101labels and both ZIP byte limits.

Pass / fail: Reject before unbounded inflation/allocation. Browser stays responsive. Error identifies the violated limit. Never execute pickle or scripts.

Write/run here: tests/unit/data.test.ts

GEO-01 · Coordinates and yaw A

Procedure: Asymmetric box4×2×2 with90° yaw; boundary points; inverse transform; sourceOrigin translation;0°,90°,180° and negative yaw; xyzw quaternion order; pitched quaternion.

Pass / fail: Rotated support selects correct points; roundtrip label tolerance1e-5m/radian; pitched/unnormalized quaternions rejected. Display scale never changes source numbers.

Write/run here: tests/unit/geometry.test.ts

GEO-02 · Oriented IoU D

Procedure: Analytic cases: identical boxes1; disjoint0; axis overlap1/3; zero-height overlap0; rotated elongated boxes crossing with expected independent polygon result. Compare TS and SQL result vectors.

Pass / fail: Error≤1e-6 for known volumes. Duplicate only same class/different IDs with IoU>=0.90. Rotated boxes must not use AABB IoU.

Write/run here: tests/unit/geometry.test.ts; tests/sql/review.sql

GEO-03 · Proposal bounds and occlusion D

Procedure: 19 vs20 fit points; missing rear surface; two adjacent objects; no eligible points; noisy outlier; rotated candidate; boundary clamp.

Pass / fail: Insufficient input refuses; centre shift≤0.5m, each size±20%,yaw±15°; proposal never writes source; support numbers reproducible. Occluded fit warning visible.

Write/run here: tests/unit/geometry.test.ts

CHECK-01 · Candidate reports and worker races D

Procedure: 4 vs5 support points;0.90 IoU boundary;20% dimension threshold;dt0,1 and>1; missing track in next frame; cancelled frame job.

Pass / fail: Deterministic list and metric provenance; low support is a suspect only; stale results cannot change current frame/selection.

Write/run here: tests/unit/geometry.test.ts; tests/unit/review.test.ts

EDIT-01 · All review decisions C/D

Procedure: Preview/reject, manual nudge/resize/yaw, approve double-pinch, keep reason, duplicate removal confirmation and undo. Switch frame after proposal.

Pass / fail: Reject source unchanged; approve one mutation; stale preview blocked; removal only selected frame occurrence; undo exact restoration including metadata/verdict.

Write/run here: tests/unit/review.test.ts; tests/e2e/review.spec.ts

SAVE-01 · Atomic save and idempotency B/D

Procedure: Disconnect before/after server commit; retry same request UUID; two tabs same base revision; simultaneous calls; invalid box midway; last-edit undo.

Pass / fail: One revision/audit only; no partial save; same request returns same result; stale client conflicts; no lost update; ACK drives Saved.

Write/run here: tests/sql/review.sql; tests/e2e/review.spec.ts

SAVE-02 · Recovery and delete B/E

Procedure: Refresh with pending draft; project switch; signout; storage quota error; upload timeout; delete network failure; reload cleanly; expired auth.

Pass / fail: User sees pending vs committed; one recoverable draft for same owner/hash; private content cleared at signout; staged upload/delete eventually cleaned; no ready project with missing source.

Write/run here: tests/e2e/review.spec.ts

SEC-01 · Auth, privacy and authorization B/E

Procedure: Two real users + guest. Direct RPC/table/storage attempts using other IDs; guest upload; forged/expired/missing JWT; manipulated origin, huge body, arbitrary tools; inspect built assets and network logs.

Pass / fail: Owner isolation holds; client cannot write revisions/budgets directly; unauthorized requests do no privileged work; no private secrets in bundle/logs;60s signed URLs and24h guest cleanup tested.

Write/run here: tests/e2e/security.spec.ts; tests/sql/review.sql

AUTH-01 · Usable account entry B/E

Procedure: OTP delivered to outside user; wrong/expired code; resend cooldown; captcha fail; actual Quest browser virtual keyboard; same permanent account on laptop and Quest.

Pass / fail: Codes work; invalid code never authenticates; errors actionable; user sees same private project across devices; no controller needed for code entry in tested path.

Write/run here: tests/e2e/security.spec.ts; tests/manual/quest.md

AI-01 · Live useful tool behavior D/E

Procedure: 20 scripted review requests:5 low support,5 duplicate,5 dimension jump,5 sparse/valid cases. Record real provider transcript with tools/results and expected safe outcome.

Pass / fail: At least18/20 valid tool plans with traceable measurements;0 automatic commits;0 invented numeric measurements; ambiguous cases say uncertainty.10/10 core demo runs complete without provider/tool failure at rehearsal.

Write/run here: tests/manual/quest.md + anonymized live transcripts

AI-02 · Agent boundary and abuse D/E

Procedure: Prompt injection in label strings; unknown tools; bad IDs; stale revision;4th round; oversized results; provider429/timeout; concurrent quota reservations; consent false.

Pass / fail: Reject unsafe calls; no save/delete action;3 rounds/8 tool calls maximum; provider failures honest; no raw point clouds or private URLs sent; budgets atomic; consent false gives zero provider requests.

Write/run here: tests/unit/agent.test.ts; tests/e2e/security.spec.ts

EXPORT-01 · Actual usable corrected data D/E

Procedure: Import real clip; approve one known box change; keep one issue; remove one known duplicate; export; independent Python validate; reimport; undo and export again.

Pass / fail: All original point member hashes unchanged. Only approved geometry/frame occurrence changes; metadata/IDs/classes preserved; correct source-world reconstruction; audit matches versions; files readable by independent validator.

Write/run here: tools/converter/validate.py; tests/e2e/review.spec.ts

XR-01 · Hands end to end C/E

Procedure: Quest3, controllers unpaired. Fresh open, CAPTCHA, demo/tutorial, enterVR, select, inspect, frame change, isolate/reset, manual edit, preview/reject, approve,undo,export,exit and resume. Test both hands, tracking loss and sleep.

Pass / fail: 3 fresh tester attempts complete without controller/desktop rescue; important labels readable; no accidental confirm; every action seated within2ft reach radius; useful task finishes≤10min; reset returns to safe state.

Write/run here: tests/manual/quest.md; real recording

PERF-01 · Hardware load and responsiveness C/E

Procedure: Record headset/browser/build. Real maximum valid frame200kpoints/100boxes;10frames permitted but only current+next point buffers in memory. Run10min after thermal warmup, including frame changes and worker checks.

Pass / fail: No sustained1s interval below60fps during steady review; p95 app frame interval≤16.7ms excluding explicit initial load; no memory crash. Target72fps. Frame swap≤1s warmed; analysis≤2s; selected UI response≤150ms. Record actual numbers, not display refresh alone.

Write/run here: tests/manual/quest.md; performance CSV

DEMO-01 · Judge access and disclosed errors E

Procedure: Fresh no-account session from production HTTPS on Quest; live CAPTCHA; clone real demo; review/save/export/reset; quota exceeded; return after guest expiry.

Pass / fail: No payment/email requirement; source and injected error notice visible; one guest project; original points real; expires predictably; model-down state not disguised as AI.

Write/run here: tests/e2e/demo.spec.ts; tests/manual/quest.md

USER-01 · Value evidence E

Procedure: Three intended reviewers;6 matched tasks each,3desktop and3VR, alternate order, independent correct-answer reference. Include a valid occluded label that should be kept. Collect time, errors, comfort1–5 and useful/not useful explanation.

Pass / fail: Each user completes useful export; total accuracy≥90% with0 destructive changes on the valid/occluded control;≥2/3 call the difficult-review loop useful. Report raw median time and limitations. Claim speed advantage only if observed without lower accuracy.

Write/run here: tests/manual/reviewer-study.csv

RELEASE-01 · Reproducible live release F

Procedure: Fresh install using lockfiles, CI, staging migration restore rehearsal, production email/guest/provider check, old-browser reload/cache, public judge URL,video duration and final submit receipt.

Pass / fail: No critical failures; correct commit and environment; account eligibility recorded; evidence fields filled; no fake product claims; accessible till11Dec. Production audit high/critical findings fixed or individually assessed with written non-exploitability evidence.

Write/run here: scripts/release-check.mjs; Guide06
